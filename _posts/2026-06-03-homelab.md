Pour ce premier article, ça sera la description du HomeLab utilisé pour la série d'article sur l'univers de la conteneurisation 

## Matériel

- NAS Synology DS923+
- Serveur sous Debian 13

Contrainte technique, le NAS ayant 2 ports Ethernet, ne pas utiliser un switch en plus

## Installer le serveur Debian (tuto succinct)

Options d'installation :

- ISO : Debian 13 netinstall
- Langue : Français
- Partitionnement : Assisté — LVM sur sda uniquement
- Schéma : Tout dans une seule partition
- Logiciels : Utilitaires système + Serveur SSH uniquement (pas de GUI)
- GRUB : sur /dev/sda

```
sda1  →  /boot      (976MB, ext4)
sda5  →  LVM PV     (237.5GB)
            └── blackwall-vg
                ├── root    225.4GB  /
                └── swap_1   12.1GB  [SWAP]
```

Création de sdb

```bash
pvcreate /dev/sdb
```
```bash
vgcreate vg_data /dev/sdb
```
```bash
lvcreate -l 100%FREE -n lv_docker vg_data
```
```bash
mkfs.ext4 /dev/vg_data/lv_docker
```
Séparer le stockage Docker sur un volume LVM dédié (sdb) isole les I/O des conteneurs du système, évite qu'un docker pull massif sature la partition root, et simplifie les snapshots ou l'extension future.

```bash
mkdir -p /var/lib/docker
```
```bash
echo '/dev/vg_data/lv_docker  /var/lib/docker  ext4  defaults  0  2' >> /etc/fstab
```
```bash
mount -a
```
```bash
systemctl daemon-reload
```

## Configuration Iptables du NAS

Ne pouvant pas faire certaines manipulations à travers l'interface interface graphique du NAS.

Utilisation du script ci-dessous 
```bash
# Autoriser le trafic depuis la DMZ vers Internet
iptables -A FORWARD -i ovs_eth1 -o ovs_eth0 -j ACCEPT
# Autoriser les réponses établies
iptables -A FORWARD -i ovs_eth0 -o ovs_eth1 -m state --state RELATED,ESTABLISHED -j ACCEPT
# NAT masquerading vers la Livebox
iptables -t nat -A POSTROUTING -o ovs_eth0 -j MASQUERADE
```
[Script iptables NAS Synology](https://github.com/RubberDucking35/Iptable-NAS-Synology/tree/main)

Avec une tache planifiée à chaque redémarrage car l'Iptable se remet à zéro après chaque démarrage ([documentation iptables](https://wiki.debian.org/iptables)).

Linux flush les règles au reboot, d'où la nécessité du script automatique.

Pas de iptables-persistent et cette architecture représente un risque mais cela reste du HomeLab
